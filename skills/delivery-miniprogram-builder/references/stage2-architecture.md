# 阶段二：从资料推导架构

## 为什么要从功能推，而不是从行业模板推

「换一份客户资料会产出不同架构」是这一段的验收点。如果先摆出首页、分类、列表、我的四模块再往里填内容，无论客户是谁，架构都长一样，只是文案不同。让功能清单反过来决定页面与模块，架构自然带上这家客户的独特动线。

## 输入

附件 01 章节的 `F-xx` / `X-xx`，以及附件 00 台账里状态为「已确认」的 `R-xx`（字段、场景细节）、`C-xx`（合规对数据与展示的约束）、`E-xx`（已接接口能力）。待确认与冲突的事实块不进入推导；主文件判「暂缓」时，本章节只标注「未启动：待补齐」，不产出 `P/M/D/I-xx`。

## 推导顺序

1. **画场景动线**：按 `R-xx` 里的核心场景，写出用户从进入到完成目标的步骤序列。步骤来自资料，不来自「小程序一般怎么做」。
2. **动线转页面 `P-xx`**：一个页面承载动线上一段连续的步骤；只有当状态、数据或跳转目的明显不同时才拆页。每个 `P-xx` 必须写「派生自哪个 `F-xx`」和「为什么需要这一页」。**任何找不到 `F-xx` 的页面都要删掉或补依据**——这是识别套模板最有效的检查。
3. **职责转模块 `M-xx`**：按数据与职责边界划分（例如「预约时段计算」「资质信息展示」「图片资源加载」），不按页面名划分。模块要说明被哪些页面复用。
4. **字段转数据 `D-xx`**：字段名、类型、必填、来源，全部取自需求文档、原型标注或接口返回。资料里没给的字段写「待补」，不要凭行业经验设计一套「完整」的数据结构。
5. **接口 `I-xx`**：优先登记客户「已接好的图片调用接口」等 `E-xx`，写清用途、鉴权、返回字段、失败态。需要但尚未提供接口的，标「待联调」并列入验收清单。
6. **存储决策**：判断数据放本地还是云端。需要跨用户共享、登录、后台维护、文件或 LLM 能力时选云端；只用本机状态即可时选本地。这个决定直接对应内置 `mini-program-development` 的第 2、4、5 步路径，写进交接规格，避免下游反复改写数据层。

## 反模板自检

把客户名、行业名遮住，只看架构文档，问三个问题：

- 还能看出这家客户的用户在做什么吗？看不出，说明页面是按通用骨架排的。
- 有没有页面与任何 `F-xx` 无关？有，就是套模板残留。
- 把资料换成另一家客户，页面数、模块划分、数据实体会不会变？不会变，说明架构不是推导出来的。

另外核对 `X-xx`：不做/后置的项有没有在架构里悄悄出现。再核对一遍主文件：依赖待确认或冲突事实块的部分有没有被写成确定页面。

## 产出格式（附件 `01 开发接手包.md` 的 02 章节）

```markdown
# 02 架构设计

## 推导说明
架构由 [F-01] [F-02] 与台账 [R-02] [C-01] 推导，未采用固定模块骨架。

## 场景动线
（从 R-xx 摘出的步骤序列，每步标注依据）

## 页面

| ID | 页面 | 派生自 | 为什么需要这一页 | 关键状态 |
|---|---|---|---|---|
| P-01 | （页面名） | [F-01] [R-02] | 动线第 2 步需独立完成 X | loading / empty / error |

## 模块

| ID | 模块 | 职责 | 被哪些页面复用 | 依据 |
|---|---|---|---|---|
| M-01 | （模块名） | | [P-01] [P-02] | [F-01] |

## 数据实体

| ID | 实体 | 字段 | 字段来源 | 状态 |
|---|---|---|---|---|
| D-01 | （实体名） | 字段: 类型 | [R-03] / [I-01] | 已确认 / 待补 |

## 接口

| ID | 接口 | 用途 | 鉴权与返回 | 状态 |
|---|---|---|---|---|
| I-01 | （客户已接好的图片接口） | | [E-01] | 已接好 / 待联调 |

## 存储决策
（本地 / 云端 + 理由 + 对下游路径的影响）

## 链路表（功能 → 页面 → 模块 → 数据/接口）

| 功能 | 页面 | 模块 | 数据 / 接口 |
|---|---|---|---|
| F-01 | P-01 | M-01 | D-01、I-01 |

## 合规约束落点
（每条 C-xx 落在哪个页面或数据上，例如资质展示、隐私字段、禁用表述）
```

## 交给第 3 段的东西

页面清单 `P-xx`、模块与数据 `M/D/I-xx`、存储决策、合规落点，以及链路表。第 3 段用它们决定模板骨架是否够用、品牌 token 要落到哪些页面，并把它们整理成给内置能力的搭建输入规格。

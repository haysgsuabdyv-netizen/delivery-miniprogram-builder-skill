# 交付记录格式骨架

这是格式模板，不是内容样例。所有表格行都要换成来自真实资料的摘录；照抄结构、不要照抄文字。**交付文档只有两份**，放在同一个交付目录下，文件名固定，便于 `scripts/check_delivery.py` 校验：

- `00-开工判断与决策清单.md` — 主文件，给项目负责人做「继续／暂缓」决定
- `01-开发接手包.md` — 附件，给开发直接接手，内含 `00`–`04` 五个章节

附件里的五个章节用一级标题 `# 00 资料台账`、`# 01 价值与功能判断` … `# 04 交付说明与验收清单`，脚本按这些标题切分章节，标题前缀不要改。验证证据是运行 `check_delivery.py --json` 的原始输出，存成 `verification.json`，不是第三份文档。

编号约定：`R` 需求 / `B` 品牌 / `C` 合规 / `E` 环境（附件 00 定义）；`V` 价值 / `F` 该做 / `X` 不做（01 定义）；`P` 页面 / `M` 模块 / `D` 数据 / `I` 接口（02 定义）；`T` 模板决策 / `BT` 品牌落地（03 定义）。引用统一写成方括号内联，例如 `[R-03]`。一个结论有多个依据就并列多个方括号。台账每条都要有「状态」：已确认 / 待确认 / 前后冲突；只有「已确认」能进入 01–03 推导。
